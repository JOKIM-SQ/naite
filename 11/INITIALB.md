# RELAY · 릴레이 initialB 등록 자료

현재 상태: **등록 자료 준비 / 공개 배포·비로그인 접속·클라우드 4개 시나리오 검증 완료 / initialB 실제 등록 미실행**. 기본 도메인 `https://s11-relay.vercel.app/`의 HTTP 200·앱 표시를 확인했으며 미리보기 배포 주소는 등록에 사용하지 않는다.

갤러리에는 아래 **사이트 URL 하나**를 입력한다. 기획서의 `data-f` 메타데이터와 정해진 문서 경로는 팀 갤러리가 읽을 수 있도록 유지했다.

```text
https://s11-relay.vercel.app/
```

## 등록 순서

1. [제출 체크리스트](SUBMISSION.md)에서 비로그인 공개 접속과 프로덕션 처리 검증 완료를 확인한다.
2. 기획서·리포트가 열리고 제목·만든 사람·스택·소개·소스가 위 표와 일치하는지 확인한다.
3. [initialB 갤러리](https://initialb.vercel.app/) 상단의 **“배포 URL을 붙여넣고 엔터 — 그게 제출이다”** 입력란에 위 주소를 붙여 넣는다.
4. 사용자가 최종 등록할 때 **Enter** 또는 **드랍** 버튼을 누른다. 이 동작이 실제 제출이다. 등록 후 S11 카드와 링크를 확인한다. 현재 작업에서는 제출하지 않았다.
5. 팀 비교표가 필요하면 [스택 리포트](https://s11-relay.vercel.app/docs/report.html)의 비교표 한 줄 복사 버튼을 사용한다. 미측정 시간과 평가 필드는 `기록 없음`이다.

## 배포 후 Inngest 연결 확인

프로덕션 환경의 `INNGEST_SERVE_ORIGIN`은 `https://s11-relay.vercel.app`으로 지정한다. 로컬의 `INNGEST_DEV=1`은 프로덕션 설정과 별개다. 배포 후 공개 기본 도메인을 확인하고 `PUT https://s11-relay.vercel.app/api/inngest`로 앱을 등록한다. 명령은 [README](README.md)의 프로덕션 연결 절에 있으며 키 인자는 필요하지 않다.

등록 응답만으로 문의 처리 성공을 판정하지 않는다. 이번 배포에서는 새 실제 문의로 일반·복합 문의·자동 복구·수동 복구까지 확인했다. 다음 배포에서도 접수 후 분류·초안·완료를 확인한다. 무인증 `GET /api/inngest`의 401은 SDK 프로덕션 보호 동작이다. initialB에는 이 API 경로가 아닌 사이트 URL 하나를 입력한다.

## 시연 절차

1. 새 문의 → 예시 · 결제 · 환불 → 문의 접수하기 → 분류·답변 초안
2. 새 문의 → 예시 · 복합 문의 → 문의 접수하기 → 검토 필요·사유
3. 새 문의 → 예시 · 기술 지원 → 데모 시나리오 설정 → 첫 분류 실패 → 자동 재시도 → 접수 → 완료
4. 새 문의 → 예시 선택 → 데모 시나리오 설정 → 계속 실패 → 최종 실패 표시 → 접수 → 최종 실패
5. 다시 처리하기 → 새 접수 기록 → 분류·답변 초안 완료

데모 주제는 **“이걸 n8n으로 했으면 몇 분이었을까”**다. n8n 소요 시간과 전체 3분 시연 시간은 미측정이다. 로컬과 공개 프로덕션에서 각각 4개 합성 시나리오의 완료를 확인했다. 개별 결과를 일반 정확도·처리 속도 보장으로 확대하지 않는다. 모델 confidence는 실제 정확도가 아니다.

회원가입·로그인, 외부 메일함 연결, 답변 외부 발송은 만들지 않았다. 응답은 사람이 사실관계를 확인하는 초안이다.
