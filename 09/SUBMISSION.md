## 검증 현황

최종 125/125개 자동 테스트·타입·린트·빌드와 독립 리뷰 CLEAR/APPROVE를 확인했습니다. 운영 Supabase는 실제 SDK 두 검증 계정으로, 로그인 후 브라우저 기능은 테스트 인증 세션으로 검증했습니다. 공개 앱의 Google 로그인 화면 진입과 정확한 공개 복귀 주소는 확인했고, 실제 Google 계정 승인 전체 왕복은 미실시입니다. 과거 91개 통과는 이전 게시 시점의 기록입니다.

| 시연 준비 | 아래 순서 준비. 3분 이내 리허설 시간은 미측정 |

URL은 JPG·PNG·WebP의 공개 직접 주소여야 합니다. 제공자의 CORS 설정·접근 제한으로 실패하면 원본 파일 업로드를 안내합니다. URL 다운로드는 12MiB·15초로 제한합니다. 게스트 보드는 이 브라우저·이 주소에 한정됩니다. Google 로그인 후 같은 계정의 개인 보드를 불러오며, 브라우저 카드는 명시적 가져오기로 복사하고 로컬 원본을 보존합니다.

개인 보드 배포 설정: `SUPABASE.sql` 실행, `SUPABASE_URL`·`SUPABASE_PUBLISHABLE_KEY` 설정, Google PKCE 공개/3090 복귀 주소 등록. 앱에는 service_role를 넣지 않습니다. DB `s09_cards`와 비공개 버킷 `s09-chroma-images`는 계정별 RLS로 보호합니다. 오래된 탭의 저장은 revision CAS로 거절하며 파일 삭제 실패는 `s09_image_cleanup`에서 재시도합니다.

## initialB 등록 방법

1. https://initialb.vercel.app/ 의 URL 입력란에 `https://s09-chroma.vercel.app/`를 넣고 드롭합니다.
2. 생성된 S09 Chroma 카드의 만든 사람·기획서·리포트·소스 링크를 확인합니다.
3. https://initialb.vercel.app/compare.html 의 스택 리포트 반영을 확인합니다.

현재 갤러리는 URL 드롭 시 `/docs/plan.html`과 `/docs/report.html`의 data-f 값을 읽습니다. 제출 문서를 나중에 변경하면 같은 URL을 다시 드롭합니다. 별도 슬라이드는 필요하지 않습니다. 이번 작업은 게시 준비까지이며 실제 갤러리 등록은 실행하지 않았습니다.

## 3분 시연 순서

1. 공개 앱을 열고 JPG 파일을 놓거나 `https://upload.wikimedia.org/wikipedia/commons/3/3a/Cat03.jpg`를 URL 폼에 붙여넣어 추가합니다.
2. 저장된 카드의 대표색 5개를 보여주고 색 하나를 눌러 HEX를 복사·붙여넣기합니다.
3. 원본·픽셀 탭을 비교하고 자세히 보기에서 독립적인 세밀 96칸 설정을 설명합니다.
4. PNG 저장을 누르고 새로고침해 팔레트·카드·설정 복원을 보여줍니다.
5. 로그인한 개인 보드에서 브라우저 카드 가져오기를 명시적으로 실행하고 계정 보드를 복원합니다. 검증은 테스트 인증 세션으로 수행했으며 실제 Google 계정 승인 전체 왕복은 미실시임을 구분합니다.
6. 카드 우상단 휴지통에서 취소와 확정 삭제를 보여주고, 기획서·리포트의 확인된 실측과 제외 범위를 설명합니다.

## 발표 근거와 안 만든 것

- 픽셀아트는 대표색 5개와 독립적입니다. 세밀 모드는 Lab 최대 64색, 픽셀 스타일은 최대 32색, 원본 모드는 샘플링한 원본 RGBA를 유지합니다.
- 세밀 워커로 메인 화면을 유지합니다. 벚꽃 사진의 로컬 재변환 1회는 약 4.45초였으며 모든 사진의 처리 시간으로 일반화하지 않습니다.
- 메인 그래픽은 12초 반복하고 모션 감소 설정에서는 정지합니다.
- 이전 배포 0.79분은 첫 프로덕션 CLI 실행부터 READY 확인까지, 이전 로딩 0.645초는 공개 주소의 첫 탐색 단일 표본입니다. 개인 보드 변경의 배포·로딩 측정, 실제 월 비용과 리허설 시간은 기록 없음입니다.
- 안 만든 것 3개: 이미지 검색·AI 생성·CORS 우회 서버 / 팀 공유 보드·실시간 동기화 / 모바일 전용 UI.
