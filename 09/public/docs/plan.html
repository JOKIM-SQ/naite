04핵심 기능 1개

Google 로그인 후 파일 또는 공개 이미지 주소를 넣으면 대표색 5개와 독립적인 픽셀아트를 공유 카드로 저장한다. 모든 인증 계정이 같은 카드를 보고 추가·편집·삭제하며 다른 사용자의 변경은 새로고침 후 확인한다. 기존 브라우저 카드는 명시적으로 가져오고 원본을 보존한다. HEX 복사·PNG 저장과 카드 직접 삭제도 지원한다. 비로그인 상태는 로그인 안내 hero만 표시하고 업로드·URL 입력·보드·로컬 카드 앱 초기화와 조회를 하지 않는다. 이 제출 문서는 공개다. 팔레트·픽셀 테마의 처리 패널은 파일 수신 직후 원본 미리보기와 파일명·배치 순서(n/N)·경과 초를 표시한다. 실제 이미지 읽기→대표색 추출→픽셀 변환→저장 단계에 맞춰 안내하며, 추출 뒤에는 실제 대표색 5개를 표시한다. URL은 다운로드 단계를 먼저 표시한다. 12초 이상 대기하면 첫 변환 준비·큰 이미지 안내를 제공하며 임의의 완료율이나 남은 시간을 표시하지 않는다. 저장 성공 후에만 완료와 카드를 표시하고, 오류 시 재시도 안내를 남긴다. 상세 재변환도 변환·저장 오버레이를 표시한다. 모션 감소 설정에서는 장식을 정지하고 단계·경과 시간 텍스트를 유지한다.

06성공 판정

  • 로그인 후 실제 이미지에서 팔레트 5칸과 픽셀아트를 생성하고 서로 다른 계정이 같은 공유 카드를 복원·편집·삭제한다. 비로그인 작업 차단, 기존 브라우저 카드의 명시적 가져오기·원본 보존, 오래된 저장 충돌 거절·삭제 직렬 처리를 확인한다. 처리 패널 추가 전 자동 테스트 134/134개·타입·린트·빌드를 통과했고 로컬 비로그인 화면의 로그인 버튼 2개·업로드와 보드 숨김을 확인했다. 운영 SQL 적용·실제 SDK 두 계정의 동일 카드 복원·상호 편집·삭제 검사를 통과했고 독립 리뷰는 CLEAR/APPROVE다. 2026-10-07 공개 배포에서 테스트 인증 세션으로 A/B 동일 카드 복원, B의 스타일 64칸 변경·PNG 37,567 bytes(1600×1075)와 A 새로고침 후 동일 해시, B 파일 업로드→A 복원·삭제, 삭제 취소·확정과 양쪽 빈 보드, 로그아웃 후 로그인 gate 복귀를 확인했다. 이전 125개 테스트와 운영 SDK 9개 검사는 개인 보드 버전의 기록이며 현재 성공 근거가 아니다. 새 처리 패널 변경은 144/144개·타입·린트·빌드와 독립 리뷰 CLEAR/APPROVE·관련 검사 60/60을 통과했다. 로컬 브라우저에서 실제 처리기·Color Thief·Worker와 격리된 IndexedDB를 연결해 원본 미리보기·실제 5색, 저장 전 카드 0개→커밋 후 1개, 모션 감소 시 애니메이션 0개와 단계 텍스트 유지, 손상 파일·URL 오류 후 복구, 상세 재변환 저장 대기·완료, 혼합 배치 1개 저장·1개 실패를 확인했다. 이는 Google 인증·클라우드 저장 왕복 검증과 구분한다. 처리 패널 1차 공개 배포 dpl_FpFupxAk9eHtmRnVpStqGUhfsS4g에서 앱 관련 4파일·문서 2파일의 HTTP 200, 코드 SHA-256의 3af08f3 일치와 당시 문서 초안 일치, 비로그인 작업 영역 hidden/inert·카드 0개·처리 패널 숨김·가로 넘침 없음을 확인했다. 이후 URL 수신 제목 수정도 전체 144개 검사와 독립 리뷰를 통과했으며 최종 후속 배포 식별자·코드 해시는 SUBMISSION.md와 SPIKE.md에 별도 기록한다.

07내 옵션 + 이유

Color Thief는 대표색 5개를 추출하고 IndexedDB는 기존 브라우저 카드의 가져오기와 원본 보존에 사용한다. Supabase Auth로 Google 로그인하며 공유 메타데이터는 Postgres s09_cards, 이미지는 비공개 Storage s09-chroma-images에 저장한다. 모든 인증 계정에 공유 읽기·수정·삭제를 허용하고 익명 접근은 거절한다. user_id는 최초 등록자로 보존하며 다른 계정이 편집해도 이미지의 creator prefix를 유지한다. 세밀 96칸은 OpenCV.js 워커의 얇은 윤곽·색 보정과 독립 Lab 최대 64색으로 만든다. 원본 RGBA와 32색 스타일도 선택하며 Python 타일 처리와 일부 픽셀 차이가 있다.

08리스크 + 검증법

걱정되는 것: 비로그인 접근·최초 등록자 변조·여러 사용자의 오래된 저장·삭제·이미지 주소의 CORS 차단.
검증: 운영 SDK 두 계정으로 기존 카드·원본 바이트 보존, 공유 읽기·편집·삭제, 등록자 보존·변조 거절, 오래된 저장 CAS 거절, 실제 객체가 있는 상태의 익명 DB·Storage·RPC 차단과 정리 대기열 0개를 확인했다. 정리 대기열은 편집·삭제 실행자 계정의 후속 작업에서만 재시도한다. 기존 s09_owner 등 정책은 ALTER POLICY로 데이터 삭제 없이 갱신한다. 공개 로그인 gate의 hidden/inert=true·카드/열린 dialog 0, 두 계정의 설정·PNG 복원·추가·삭제·로그아웃을 테스트 인증 세션으로 확인했다. 실제 Google 계정 승인 전체 왕복은 미실시다. CORS 차단은 파일 업로드로 안내한다.
