한 줄 결론

로그인한 사람들이 이미지의 색감과 픽셀아트를 함께 모으는 경우에는 Color Thief와 Supabase 공유 보드를 쓰겠다. Google PKCE 로그인 후 모든 인증 계정이 Postgres s09_cards 전체와 비공개 Storage s09-chroma-images의 같은 카드를 보고 추가·편집·삭제한다. 별도 초대 없이 공유하며 다른 사용자의 변경은 새로고침 후 확인한다. 비로그인 상태는 로그인 안내 hero만 표시하고 업로드·URL·보드·로컬 카드 앱 초기화와 조회를 하지 않는다. hero와 제출 문서는 공개다. IndexedDB의 기존 카드는 명시적 가져오기로 복사하고 원본을 보존한다. user_id는 최초 등록자로 유지하며 타사용자 편집도 creator/card/version/source|thumbnail|pixel 경로 prefix를 유지한다. 신규 등록자는 본인만 허용하고 직접 등록자 변경과 익명 접근을 거절한다. 기존 s09_owner 등 정책은 ALTER POLICY로 데이터 삭제 없이 갱신한다. 저장 revision CAS와 삭제 직렬 트랜잭션을 유지하고 파일 정리 대기열은 편집·삭제 실행자 계정의 후속 작업에서만 재시도한다. 설정은 SUPABASE.sql과 SUPABASE_URL·SUPABASE_PUBLISHABLE_KEY이며 service_role는 앱에 넣지 않는다. 현재 자동 테스트 134/134개·타입·린트·빌드를 통과했고 로컬 비로그인 화면의 로그인 버튼 2개·업로드와 보드 숨김을 확인했다. 운영 SQL을 트랜잭션으로 적용하고 실제 SDK 두 계정의 동일 카드·원본 바이트 복원, 타계정 이름/픽셀 수정·삭제, 최초 등록자 보존·변조 거절, 오래된 저장 CAS 거절, 익명 DB·Storage·RPC 차단, 무관한 타계정 경로 업로드 거절과 정리 대기열 0개를 확인했다. 독립 리뷰는 CLEAR/APPROVE이며 초기 로딩·로그아웃 경합 재현 1/1과 관련 테스트 34/34도 통과했다. 2026-10-07 공개 배포에서 테스트 인증 세션으로 A/B 동일 카드 복원, B의 스타일 64칸 변경·PNG 37,567 bytes(1600×1075)와 A 새로고침 후 동일 해시, B 파일 업로드→A 복원·삭제, 삭제 취소·확정과 양쪽 빈 보드, 로그아웃 후 로그인 gate 복귀를 확인했다. 공개 설정과 두 문서는 HTTP 200이며 /api/config는 provider·publishableKey·url만 포함한다. 기능 검증 소스는 906857d, 검증 배포는 dpl_ZRLLfYtmGRjpwzbSTeBYyYLX37AF다. 후속 문서 배포 식별자는 SUBMISSION.md와 SPIKE.md에 별도로 기록한다. 이전 125/125개 테스트·타입·린트·빌드·독립 리뷰 CLEAR/APPROVE와 운영 SDK 두 계정 9개 검사는 개인 보드 버전 기록이며 현재 공유 보드 성공 근거가 아니다. 실제 Google 계정 승인 전체 왕복은 미실시다. 세밀 96칸·독립 Lab 최대 64색, 원본 색 유지·32색 스타일을 제공한다. 제외 범위는 이미지 검색·AI 생성·CORS 우회 서버 / 초대·권한 관리·실시간 동기화 / 모바일 전용 UI다. 첫 저장 6분·벚꽃 로컬 변환 약 4.45초와 과거 91개 테스트·배포 0.79분·로딩 0.645초는 이전 게스트 게시 기록이다. 현재 공유 보드 배포·로딩 시간, 실제 월 비용과 3분 시연 리허설은 기록 없음. 상세 근거와 검증 한계는 SPIKE.md에 기록한다.
