# S09 Chroma — 컬러와 픽셀을 함께 모으는 보드

## 확정한 범위

- 최신 첨부 S09 과제와 실제 가이드의 Color Thief + IndexedDB를 따른다. 루트 CLAUDE.md의 오래된 S09 서버리스·크론 설명은 이번 과제에 적용하지 않는다.
- 이미지 파일을 한 번 드롭/선택하면 대표색 5개와 픽셀아트를 함께 생성하고 자동 저장한다.
- 픽셀아트는 팔레트 추출과 독립된 처리다. 새 사진의 기본은 얇은 윤곽·Lab 최대 64색의 세밀 96칸이다. 원본 색 유지와 독립 32색 픽셀 스타일도 제공한다.
- 한 카드에서 원본/픽셀아트 전환, HEX 복사, 픽셀 크기 변경, PNG 다운로드, 제목 수정·삭제.
- Google 로그인은 필수다. 비로그인 상태는 로그인 안내 hero만 표시하며 업로드·URL 입력·보드·로컬 카드 앱 초기화와 조회를 하지 않는다. 로그인 후 모든 인증 계정이 같은 Supabase 공유 카드 전체를 복원하고 추가·편집·삭제한다. IndexedDB의 기존 브라우저 카드는 명시적으로 가져오며 원본을 보존한다.
- 데스크톱용으로 구현한다. 공개 이미지 URL 입력·드롭과 카드 직접 삭제를 지원한다. 제외 범위는 이미지 검색·AI 생성·CORS 우회 서버 / 초대·권한 관리·실시간 동기화 / 모바일 전용 UI다.

## 성공 조건

1. 실제 사진을 업로드하면 대표색 5개와 픽셀아트가 한 카드에 생성된다.
2. 픽셀아트에 대표색 5개 제한이 적용되지 않는다. 세밀 모드는 최대 64색, 스타일은 최대 32색이며, 원본 모드의 샘플링한 색·알파가 보존된다.
3. 서로 다른 로그인 계정이 새로고침과 새 탭에서 동일한 공유 카드·이미지·설정을 복원하고 상대방 카드를 편집·삭제한다. 실시간 자동 갱신은 하지 않는다.
4. 색상 클릭 후 붙여넣을 수 있고 변환 PNG를 다운로드할 수 있다.
5. 잘못된 파일·추출/저장 실패를 완료로 표시하지 않는다.
6. 문서 템플릿 CSS·data-f를 보존하고 미측정 값은 기록 없음으로 남긴다.
7. DB·비공개 이미지의 익명 접근을 거절하고 모든 인증 계정에 공유 읽기·수정·삭제를 허용한다. 신규 등록자는 본인만 허용하며 최초 등록자 변경을 차단한다. 저장 revision CAS와 삭제 직렬 트랜잭션과 파일 정리 대기열 재시도를 유지한다.
8. 카드 직접 삭제에서 취소·실패는 카드를 보존하고, 성공한 대상만 삭제한다. 로컬 카드 가져오기는 중복을 건너뛰고 부분 성공과 브라우저 원본을 유지한다.
9. 비로그인·설정 누락·세션 종료 시 앱을 초기화하거나 로컬 카드를 조회하지 않고 로그인 안내만 표시한다.
10. 파일 수신·실제 처리 단계·저장·오류를 구분하고, 원본 미리보기·추출색·경과 초·배치 순서를 보여준다. 모션 감소 설정에서도 단계 텍스트를 유지하고 완료·실패 시 애니메이션·타이머·임시 미리보기를 정리한다.

## 이전 구현 이력 — 아래 테스트 수는 당시 결과

1. 완료 — 테스트를 먼저 작성하고 이미지 처리·IndexedDB·데스크톱 UI를 구현했다.
2. 완료 — 자동 처리 컨트롤러를 통합하고 타입·린트·테스트·빌드를 검증했다.
3. 완료 — 실제 브라우저에서 업로드·복원·HEX 선택 복사·PNG·실패 경로와 화면을 검증했다. 제목 저장 경합과 손상 이미지 오류 안내도 회귀 테스트 후 수정했다.
4. 완료 — 기획서·리포트·실측 기록을 마무리했다. 전체 24개 테스트·타입·린트·빌드와 문서 템플릿 보존 검사를 통과한 소스를 커밋한다.

초기 구현 단계에서는 공개 배포 요청이 없었고, 로컬 검증과 배포 가능한 결과물을 완료 기준으로 삼았다.

이후 게시 준비 요청으로 공개 배포·원격 반영·제출 문서 준비를 이번 마무리 범위에 추가했다.

## 픽셀아트 품질 개선 이력 — 사용자 승인

- ‘원본 색 유지’와 ‘픽셀 스타일’ 두 모드를 제공한다. 원본 모드의 RGBA 샘플링 계약은 유지한다.
- 당시 새 이미지 기본은 픽셀 스타일 64칸이었다. 현재는 아래 세밀 96칸 승인으로 대체됐다. 기존 카드의 모드 정보가 없으면 원본 색 유지로 해석하고 저장된 이미지도 보존한다.
- 픽셀 스타일은 잔질감과 튀는 색을 줄이고 윤곽을 유지하며, 별도 32색으로 단순화한다. 디더링은 사용하지 않는다. 대표색 5개 추출은 원본에서 독립적으로 실행한다.
- 모드·밀도를 변경하면 원본 Blob에서 재생성하고, 저장이 끝난 뒤 화면에 반영한다. 실패 시 기존 설정·이미지를 유지한다.
- 픽셀 카드에서는 이미지를 잘라내지 않고 전체를 보여준다. PNG는 격자를 정수 배율로 확대한다.

## 개인 보드와 직접 삭제 — 이전 버전 기록

- Supabase Auth의 Google PKCE 로그인과 계정별 Postgres `s09_cards`·비공개 Storage `s09-chroma-images`를 연결한다. 테이블·버킷 RLS는 본인 데이터만 허용한다.
- 게스트 IndexedDB는 유지한다. 로그인 후 브라우저 카드 가져오기를 명시적으로 실행하며 기존 ID는 중복 저장하지 않고 로컬 원본도 지우지 않는다.
- 클라우드 저장 revision CAS로 여러 탭의 덮어쓰기를 거절한다. 카드 삭제·이미지 교체와 정리 대기열 등록을 한 트랜잭션으로 처리하고 Storage 정리 실패를 이후 작업에서 재시도한다.
- 카드 우상단 삭제 버튼은 기존 확인 창과 직렬 저장 경로를 공유한다. 취소·Escape·저장 실패·다른 카드 상세·진행 중인 변환과의 경합을 검증한다.
- 설정은 `SUPABASE.sql`, `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`를 사용한다. 공개 주소와 3090 로컬 주소를 PKCE 복귀 주소로 등록한다. service_role는 앱에 포함하지 않는다.
- 완료 — 최종 125/125개 테스트·타입·린트·빌드 통과, 독립 리뷰 CLEAR/APPROVE·미해결 P1/P2 없음. 운영 DB의 두 테이블 RLS·비공개 버킷과 실제 SDK 두 계정의 9개 검사를 확인했다.
- 완료 — 로컬 게스트 8개에서 취소 8개 유지·확정 7개, 계정 보드의 기존 1개에 브라우저 7개 가져오기 후 8개, 원본 보존을 확인했다. 공개에서 8개 복원·이름/픽셀 설정/PNG 저장 유지·삭제 8→7을 확인했다. 로그아웃 후 공개 게스트 1개와 로컬 게스트 7개로 각각 복귀했다.
- Google 로그인 화면 진입과 정확한 공개 복귀 주소는 확인했다. 실제 Google 계정 승인 전체 왕복은 미실시이며 로그인 후 기능 검증에는 테스트 인증 세션을 사용했다. 개인 보드 배포·로딩 시간은 미측정이다. 위 125개 결과를 포함한 이전 기록은 현재 공유 보드 검증과 구분하며 실제 initialB 등록은 하지 않는다.

## 로그인 필수 공유 보드 — 처리 패널 추가 전 검증 이력

- 모든 인증 계정이 하나의 공유 보드를 사용한다. 별도 초대 멤버·역할 설정은 없으며 다른 사용자의 변경은 새로고침 후 확인한다.
- 비로그인 상태는 로그인 안내 hero만 표시한다. 업로드·URL 입력·보드 및 로컬 카드 앱 초기화·조회는 로그인 이후로 제한한다. 설정 누락·연결 실패 시에도 게스트로 우회하지 않는다.
- 로그인 후 `s09_cards` 전체를 복원한다. 기존 IndexedDB 카드는 명시적 가져오기로만 복사하며 원본을 보존한다.
- `s09_cards.user_id`는 최초 등록자를 유지한다. 타사용자 편집도 비공개 `s09-chroma-images`의 `creator/card/version/source|thumbnail|pixel` 경로 prefix를 유지한다. 신규 카드는 본인 등록자로만 생성하며 직접 등록자 변경·익명 접근을 차단한다.
- 기존 `s09_owner` 등 RLS 정책은 `SUPABASE.sql`의 ALTER POLICY로 갱신하고 DB 행·이미지는 삭제하지 않는다. 저장 CAS와 삭제 직렬 트랜잭션과 이미지 정리 재시도를 유지한다. 정리 대기열은 편집·삭제 실행자 계정에 귀속되며 해당 계정의 후속 작업에서만 재시도한다.
- hero와 제출 문서는 공개로 유지하고 앱 작업 영역에 로그인을 요구한다. 계정별 개인 보드 격리는 현재 제공하지 않는다.
- 이 시점의 자동 테스트 134/134개·타입·린트·빌드는 통과했고 로컬 비로그인 화면의 로그인 버튼 2개·업로드와 보드 숨김을 확인했다. 운영 SQL을 트랜잭션으로 적용하고 실제 SDK 두 계정의 동일 카드·원본 바이트 복원, 타계정 이름/픽셀 수정·삭제, 최초 등록자 보존·변조 거절, 오래된 저장 CAS 거절, 익명 DB·Storage·RPC 차단, 무관한 타계정 경로 업로드 거절과 정리 대기열 0개를 확인했다. 독립 리뷰는 CLEAR/APPROVE이며 초기 로딩·로그아웃 경합 재현 1/1과 관련 테스트 34/34도 통과했다. 2026-10-07 공개 배포에서 테스트 인증 세션으로 A/B 동일 카드 복원, B의 스타일 64칸 변경·PNG 37,567 bytes(1600×1075)와 A 새로고침 후 동일 해시, B 파일 업로드→A 복원·삭제, 삭제 취소·확정과 양쪽 빈 보드, 로그아웃 후 로그인 gate 복귀를 확인했다. 기능 소스 `906857d`와 검증 배포 `dpl_ZRLLfYtmGRjpwzbSTeBYyYLX37AF`를 후속 문서 배포와 구분한다. 상세 결과는 SPIKE.md와 제출 문서에 기록한다. 실제 Google 계정 승인 전체 왕복도 미실시다.

## 처리 상태 패널 — 현재 변경

- 팔레트·픽셀 테마의 처리 패널은 파일 수신 직후 원본 미리보기와 파일명·배치 순서(n/N)·경과 초를 표시한다. 실제 이미지 읽기→대표색 추출→픽셀 변환→저장 단계에 맞춰 안내하며, 추출 뒤에는 실제 대표색 5개를 표시한다. URL은 다운로드 단계를 먼저 표시한다. 12초 이상 대기하면 첫 변환 준비·큰 이미지 안내를 제공하며 임의의 완료율이나 남은 시간을 표시하지 않는다. 저장 성공 후에만 완료와 카드를 표시하고, 오류 시 재시도 안내를 남긴다. 상세 재변환도 변환·저장 오버레이를 표시한다. 모션 감소 설정에서는 장식을 정지하고 단계·경과 시간 텍스트를 유지한다.
