날짜: 2026-10-15. 가이드: https://initialb.vercel.app/guide.html#s10

최신 상태: 사용자 승인 확장 1·2·3 및 공개 배포 완료. https://s10-galpi.vercel.app/ 에서 로그인 없이 사용할 수 있다. 자연어 검색·검색 근거·TXT/Markdown 가져오기와 IndexedDB 보관을 제공하며 최종 102/102 검사·타입·구문·빌드를 통과했다. initialB 등록 준비는 완료했고 실제 갤러리 등록은 실행하지 않았다. 아래 초기 구현 수치는 `80c8c7b` 당시의 이력이며, 최신 결과는 문서 하단의 확장·공개 배포 기록을 따른다.

## 선택과 범위

사용자가 Fuse.js와 예시 사내 문서·FAQ 20개를 선택했다. Node ESM·정적 HTML/CSS/JavaScript를 사용하고, Fuse.js 7.5.0을 실제 검색 경로에 연결했다. 브라우저 import map은 빌드 시 복사한 `public/vendor/fuse.mjs`를 사용한다. MIT 라이선스도 함께 복사한다. 로그인·DB·필터·AI 응답·문서 관리 기능은 구현하지 않았다. 예시임을 헤더·푸터·문서 내용에 표시한다.

공식 문서는 Context7의 `/krisk/fuse`와 설치 패키지의 타입 선언으로 확인했다. 참고: https://github.com/krisk/fuse 및 https://www.fusejs.io/api/options.html . 제목·키워드·요약·본문에 가중치를 주고 Fuse의 실제 점수로 정렬한다. 검색어·정답 ID에 따른 결과 분기는 없다.

## 한국어 처리에서 막힌 지점

1. 음절 단위 비교에서는 `연챠`, `비밀번오` 등의 오타가 불리해 공백·기호 정리와 Hangul NFD 자모 분해를 사용했다.
2. 처음의 고정 개발 평가 36개는 통과했지만, 별도로 고정한 사용 질의 10개 중 `연챠는 어디서 신청해요?`, `비밀번호를 잊어버렸어요`, `비용정산`, `노트북이 고장났어요`가 빈 결과였다. 핵심 명사와 서술형 어절을 모두 요구한 것이 원인이었다. 제한적인 조사·어미 정리와 문서 키워드 어휘에 근거한 붙임 명사 분리로 보완했다. 문서·질의·기대 문서 ID는 바꾸지 않았다.

전문 형태소 분석이나 의미 검색이 아니다. 초기 구현에서 `연차 쓰고 싶어요`는 빈 결과였고, 아래 승인된 확장 이후에는 정상 검색된다. 개발 평가의 성공률을 모든 한국어 질문의 정확도로 일반화하지 않는다. 붙임 명사는 등록된 문서 키워드 범위에서만 분리한다.

- 추가 질의 10개 모두 실제 UI 이벤트를 거쳐 정답이 top3에 표시됐다.

## 승인된 확장 1·2·3 — 최종 검증

사용자가 자연스러운 한국어 검색, 검색 근거 하이라이트·관련 문단 이동, TXT/Markdown 업로드와 브라우저 보관을 승인했다. 기존 단일 검색창·필터 없음·예시 20개를 유지한다. 업로드 문서는 같은 브라우저·같은 출처의 IndexedDB에 보관하며 서버로 전송하거나 다른 기기에 동기화하지 않는다.

- `연차 쓰고 싶어요`, `비번 까먹었어` 등 새 자연어 12개를 모두 기대 문서 1위로 확인했다. 기존 36개와 추가 사용 질의 10개도 유지해 개발 검색 질의는 총 58개다. 이는 고정 개발 평가이며 일반 한국어 정확도 측정값은 아니다.
- 제목·스니펫·원문은 원래 문자열의 UTF-16 범위로 강조한다. 자모 분해된 입력과 이모지 앞의 문자열도 원문을 보존한다. `연차` 검색에서 무관한 `연락`까지 강조되던 문제를 회귀 검사로 수정했다.
- 실제 관련 문단이 있을 때만 이동 버튼을 제공한다. 긴 검증 문서의 31번째 문단으로 이동하며 본문 스크롤 0→4350, 페이지 스크롤 0·검색창 위치 유지를 확인했다.
- 실제 Markdown 617 bytes·TXT 228 bytes와 잘못된 CSV 46 bytes를 함께 추가했다. 2개 저장·CSV 실패를 구분하고 입력 중인 `오로라` 검색어를 보존한 채 새 문서를 표시했다. 새로고침 후 예시 20+업로드 2=22개를 복원하고, 같은 파일 재선택은 0개 추가·총22개로 유지했다.
- 실제 File 드롭 이벤트로 긴 TXT도 저장했다. 256KiB 초과 파일은 거절하고 기존 문서·검색어·재시도 기능을 보존했다. HTML 모양의 파일 내용은 실행하지 않고 문자 그대로 표시했다.
- 문서는 파일당 256KiB, 한 번에 10개, 보관 100개·원본 합계 5MiB로 제한한다. 저장 성공은 IndexedDB 트랜잭션 완료 후에만 반환한다. 저장 0건과 뒤이은 목록 조회 실패가 겹쳐도 저장됐다고 안내하지 않는다.
- 큰 문서 근거 생성의 지연을 수정했다. 20문서·3,876,510 bytes 단일 Node 재현에서 구현자 관측은 정확 검색 1160→139ms, 오타 2201→221ms였다. 독립 재검증은 138/231ms였다. 장치·입력에 따른 최대 처리 시간을 보장하는 측정이 아니다.

최종 순차 검사 `npx tsc --noEmit`, `npm run lint`, `npm test`, `npm run build` 모두 exit 0. **102/102 pass, fail·skip 0**이며 검색 74·DOM 15·저장 11·HTTP 2개다. 독립 리뷰는 최종 세 차례 검토 후 **CLEAR/APPROVE**, 차단 사항 없음이다. 실제 브라우저 자연어 12개·원문 근거·NFD·이모지·IME 이벤트 시뮬레이션·업로드·드롭·복원·중복·용량 거절을 확인했다. 1280px와 375px에서 가로 넘침 없고 콘솔 오류도 없다.

QA 생성 문서 ID 3개만 정리한 뒤 예시 20개·내 문서 0개·추가 버튼 활성·빈 검색·강조 없음으로 복구했다. 사용자 문서는 정리 대상에 넣지 않았다. 앱 코드 변경 없이 제출 문서를 갱신하며 공개 배포·initialB 등록은 계속 미실시다.
