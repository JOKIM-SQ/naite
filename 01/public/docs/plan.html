01누가 쓰나

iBD 주간 MVP 훈련에 참가하는 팀원 3~5명. 주 1회, 금요일 데모데이 전에 자기 결과물을 제출한다. 한 사람이 18주 동안 18번 제출하므로 팀 전체로는 54~90장의 카드가 쌓인다.

02지금은

제출을 받을 곳이 아직 없다. 그래서 1주차 결과물이 곧 그 제출 창구다. 갤러리가 없으면 시트에 열 7개(스프린트·제목·만든 사람·스택 카드·옵션·URL·소개)를 손으로 채우고, 문서 링크도 매번 URL + /docs/plan.html로 손으로 조립해야 한다.

03없앨 동작 하나

시트에 열 7개를 손으로 채우는 것. URL 하나 드랍(5초)으로 대체한다 — 나머지 6개 열은 서버 함수가 /docs/plan.html에서 읽어 채운다.

04핵심 기능 1개

배포 URL을 드랍하면 서버 함수가 그 사이트의 /docs/plan.html을 읽어 카드 메타(제목·만든 사람·스택·소개·소스)를 자동으로 채우고, 스크린샷을 1회 찍어 Supabase에 저장한다.

05안 만드는 것 3개

  • 필터 심화 — 스택 칩 토글 하나만. 복합 조건·정렬 옵션·검색 결합은 다음 갤러리 버전
  • 검색 — 시즌이 다 차도 100장 남짓, 스크롤 + 스프린트 점프로 충분
  • 수정·삭제 UI — 로그인 없는 사이트에 삭제 버튼은 무방비. 잘못 드랍하면 관리자가 DB에서 지운다

06성공 판정

  • URL을 드랍하면 다른 사람 브라우저에서도 카드가 보인다 (새로고침에 카드가 늘어난다)
  • 규약 준수 사이트는 제목·만든 사람·소스가 자동으로 채워지고, 드랍 시 스크린샷 썸네일이 붙는다
  • 규약 미준수 URL은 도메인 카드로 폴백 — 드랍 실패는 없다
  • 카드가 Supabase에서 나온다 (하드코딩 아님)
  • 배포 후 initialb.vercel.app/docs/plan.html이 열린다 (셀프 드랍으로 자기 규약 검증)

07내 옵션 + 이유

Vercel Pro를 이미 구독 중이고, 붙이는 데 손이 가장 덜 가는 플랫폼이라서 골랐다. 깃 연결 → Root Directory를 01로 지정 → 끝. 빌드 설정이 없고, api/drop.js를 파일 하나 두는 것만으로 서버 함수가 된다. 1주차 결과물이 시즌 인프라가 되는 주라 호스팅 자체에 시간을 쓰지 않는 것이 선택 기준이었다. 18주를 레포 하나에 담는다는 점도 이 선택을 뒷받침한다 — Cloudflare Pages는 레포당 프로젝트 5개라 한 호스트에 몰면 6주차에 막힌다.

08리스크 + 검증법

걱정되는 것: 정적 파일 경로. 규약은 public/docs/plan.html인데 Vercel zero-config는 Root Directory를 그대로 서빙할 수도, public/을 output으로 잡을 수도 있다. 후자가 아니면 배포 URL이 /public/docs/plan.html이 되어 규약을 내가 먼저 깬다. 그 다음은 스크린샷 — 서버 함수 안에서 헤드리스 브라우저는 실행 시간·번들 크기 제한에 걸릴 수 있다.
화요일 스파이크로 확인: 01/을 Root Directory로 배포하고 initialb.vercel.app/docs/plan.html을 직접 열어본다 (안 열리면 01/docs/로 옮긴다). 스크린샷은 외부 API 1회 호출 → Supabase shots 버킷 업로드까지만 본다 — 안 되면 썸네일 없이 도메인 카드로 폴백.
