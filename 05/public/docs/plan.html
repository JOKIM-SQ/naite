01누가 쓰나

Spigen 폰 케이스 제품군을 정리·비교하는 운영 담당자. Amazon의 색상과 호환 기기 변형을 직접 기록하지 않고, 제품군 관계를 빠르게 확인하고 싶다.

02지금은

Amazon에서 색상이나 호환 기기를 바꿀 때마다 별도 ASIN을 확인하고 URL을 수동으로 기록한다. 다른 기기 탭에는 대표 ASIN만 보여서, 실제로 몇 색상이 저장될지도 저장 전에는 알기 어렵다.

03없앨 동작 하나

변형 선택기를 하나씩 눌러 색상별 ASIN과 호환 기기 모델을 옮겨 적는 동작.

04핵심 기능 1개

Amazon URL 또는 ASIN을 넣으면 서버가 Spigen 폰 케이스인지 검증하고, 판매 가능한 색상·호환 기기 파생 ASIN을 누적 수집한다. 사용자는 같은 기기의 다른 색상과 다른 기기의 전체 색상을 저장 전에 확인·선택하며, 선택 결과는 제품·호환 기기·색상 옵션 3개 Postgres 테이블과 JOIN 화면에 저장된다.

05안 만드는 것 3개

  • Spigen 외 브랜드 또는 폰 케이스 외 액세서리의 수집
  • Amazon이 제공하지 않은 색상×기기 조합을 추측해 생성하는 기능
  • 가격 이력·품절 알림·구매 기능

06성공 판정

  • Spigen 폰 케이스 URL/ASIN을 넣으면 제품명·사진·색상·호환 기기 변형이 채워진다.
  • 같은 기기·다른 색상과 다른 기기·전체 색상을 두 탭에서 선택하며, 다른 기기는 저장 전 실제 색상 수와 이름을 확인한다.
  • 선택한 ASIN은 제품·호환 기기·색상 옵션 3개 테이블에 관계로 저장되고, 메인 화면의 JOIN 결과와 기기→색상 사이드바에 함께 보인다.
  • Google OAuth로 로그인한 @spigen.com 계정만 접근하며, RLS로 다른 계정의 행은 읽거나 쓸 수 없다.

07내 옵션 + 이유

제품·호환 기기·색상 옵션을 명시적으로 연결하고 화면에서 JOIN 결과를 보여 주기 위해 Supabase Postgres를 선택했다. Google OAuth와 RLS는 @spigen.com 계정만의 데이터를 DB 계층에서 분리하고, Vercel 서버 함수의 fetch + Cheerio 파서는 Amazon 변형 페이지를 누적 수집한다.

08리스크 + 검증법

걱정되는 것: Amazon 응답 일부에서 변형 필드가 비어 있거나, 다른 기기는 대표 ASIN만 먼저 내려올 수 있다. OAuth redirect URL과 RLS 정책도 배포 환경에서만 정확히 드러난다.
화요일 스파이크로 확인: 응답을 100회까지 누적 병합하고, 파생 기기 대표 ASIN을 다시 수집해 실제 색상 수를 미리보기로 반환한다. Galaxy Z Flip 7 샘플에서 Black Sesame·Avo Green·Blueberry Navy 3개 ASIN을 확인하고, @spigen.com 로그인과 RLS 저장도 운영 배포에서 검증한다.
