# S08 Stockroom — 실시간 팀 재고 보드

## 사용자 결정

- Supabase Realtime 사용.
- Google 로그인한 팀원들이 같은 재고 보드를 공유.
- 기존 weekly-awe-project Supabase(`kmfoeoxvsadlurpmkqwh`) 재사용. 다른 주차 데이터는 변경하지 않는다.

## 핵심 흐름

Google 로그인 → 재고 보드 만들기 또는 초대 링크로 참여 → 품목 등록 → 입고/출고 → 다른 탭의 수량 자동 반영.

## 성공 조건

- 실제 Supabase에 저장한 수량을 두 탭에서 새로고침 없이 확인하고 지연 시간을 실측한다.
- 동시에 수량을 바꿔도 delta가 누락되지 않고 음수 재고가 저장되지 않는다.
- 연결 상태를 표시하고 다시 연결되면 DB 최신값을 재조회한다.
- 보드 멤버만 조회·변경·실시간 구독할 수 있다. Google 로그인만으로 모든 보드를 공개하지 않는다.
- 모바일에서 품목 등록과 수량 변경이 가능하다.
- 공개 기획서·리포트는 팀 템플릿 규약을 유지하며 관찰하지 않은 수치는 기록 없음으로 남긴다.
- 데모에서 지연 시간, 연결/충돌 처리, 비용 관찰 및 폴링 대안에 답한다.

## 범위

품목명·SKU·수량·단위·부족 기준, 원자적 입출고, 로그인과 보드 초대, 실시간 연결 상태. 한 번에 보드 하나를 표시한다. 구매·발주·바코드·CSV·회계 연동은 만들지 않는다.

## 진행 계획

1. 완료 — 가이드·공식 Realtime 문서·기존 서비스 연결 확인, 데이터 계약 및 SQL 설계. CLI의 기존 프로젝트 읽기 쿼리 성공.
2. 완료 — 테스트 우선으로 입출고/동기화와 Google 로그인·팀 보드 UI 구현. 실제 Supabase에 전용 SQL 적용.
3. 완료 — 자동 검증·실제 두 탭 측정·오프라인 복구·문서 기록 완료. 사용자가 Google 로그인 완료를 직접 확인했다. 후속 읽기 전용 조회에서 보드·멤버·품목 0개로 초기 사용 전 상태임을 확인했다.
4. 진행 중 — 별도 Vercel 프로젝트에 공개 배포하고 환경변수·OAuth 반환 주소·문서 링크를 적용한 뒤 공개 접근을 검증한다.

실제 두 탭 DOM 반영 20회: 중앙값 0.536초, p95 0.675초, 최대 0.829초. 실제 두 계정 동시 변경·재시도·권한 검증 통과. Google 로그인 완료는 사용자 확인으로 기록했다.

테스트 39/39, 타입·구문·빌드 검사 통과. 리뷰 지적 1건 수정 후 재검토 통과. 검증 전용 계정 3개와 보드는 정리했다. 공개 배포는 아직 진행하지 않았으며 배포 설정과 문서 초안은 준비했다.
