# S08 Stockroom — 실시간 팀 재고 보드

## 사용자 결정

- Supabase Realtime 사용.
- Google 로그인한 팀원들이 같은 재고 보드를 공유.
- 기존 weekly-awe-project Supabase(`kmfoeoxvsadlurpmkqwh`) 재사용. 다른 주차 데이터는 변경하지 않는다.

## 핵심 흐름

Google 로그인 → 재고 보드 만들기 또는 초대 링크로 참여 → 품목 등록 → 입고/출고 → 다른 탭의 수량 자동 반영.

## 성공 조건

- 실제 Supabase에 저장한 수량을 두 탭에서 새로고침 없이 확인하고 지연 시간을 실측한다.
- 동시에 수량을 바꿔도 delta가 누락되지 않고 음수 재고가 저장되지 않는다.
- 연결 상태를 표시하고 다시 연결되면 DB 최신값을 재조회한다.
- 보드 멤버만 조회·변경·실시간 구독할 수 있다. Google 로그인만으로 모든 보드를 공개하지 않는다.
- 모바일에서 품목 등록과 수량 변경이 가능하다.
- 공개 기획서·리포트는 팀 템플릿 규약을 유지하며 관찰하지 않은 수치는 기록 없음으로 남긴다.
- 데모에서 지연 시간, 연결/충돌 처리, 비용 관찰 및 폴링 대안에 답한다.
- 재고 목록 아래 마지막으로 수신한 수량 변경의 지연을 ms로 표시하고, 품목별 입출고 기록에서 수행자·시간·변경량·전후 재고를 확인한다.

## 범위

품목명·SKU·수량·단위·부족 기준, 원자적 입출고, 로그인과 보드 초대, 실시간 연결 상태. 한 번에 보드 하나를 표시한다. 구매·발주·바코드·CSV·회계 연동은 만들지 않는다.

## 진행 계획

1. 완료 — 가이드·공식 Realtime 문서·기존 서비스 연결 확인, 데이터 계약 및 SQL 설계. CLI의 기존 프로젝트 읽기 쿼리 성공.
2. 완료 — 테스트 우선으로 입출고/동기화와 Google 로그인·팀 보드 UI 구현. 실제 Supabase에 전용 SQL 적용.
3. 완료 — 자동 검증·실제 두 탭 측정·오프라인 복구·문서 기록 완료. 사용자가 Google 로그인 완료를 직접 확인했다. 후속 읽기 전용 조회에서 보드·멤버·품목 0개로 초기 사용 전 상태임을 확인했다.
4. 완료 — 별도 Vercel 프로젝트 `s08-stockroom`에 공개 배포. 공개 연결 환경변수 두 개를 등록했고, 실제 공개 주소의 데스크톱·모바일 화면·설정 API·문서 링크·Google 인증 시작을 검증했다. 소스와 배포 설정을 원격 브랜치에 반영했다.
5. 완료 — 사용자가 Supabase Redirect URLs에 `https://s08-stockroom.vercel.app/` 추가 완료를 확인했다. 공개 앱에서 Google 인증 화면으로 이동하는 동작을 다시 검증했다.
6. 외부 로그인 확인 대기 — 자동화 브라우저에는 Google 인증 세션이 없어 공개 주소에서 인증 완료 후 보드 화면으로 복귀하는지 사용자에게 확인을 요청했다. 반환 URL 추가 완료와 실제 로그인 완료를 구분해 기록한다.
7. 완료 — 최신 가이드·갤러리 제출 방식과 공개 문서를 대조했다. S08 전용 지침·제출 체크리스트·리포트의 폴링 비교 설명을 보완해 공개 배포했다. 템플릿 CSS·data-f 보존, 공개 문서 200·390px 가로 넘침 0, 타입·구문·테스트 39개·빌드를 확인했다. 실제 갤러리 등록과 공개 로그인 후 시연은 미확인으로 구분했다.
8. 완료 — 마지막 수량 변경의 요청 전송→Realtime 이벤트 수신 지연(ms)과 품목별 수량 조정/입출고 기록 탭을 구현했다. timestamp·재시도·오래된 구독·시계 불일치·이력 권한/페이지/경합 테스트를 먼저 추가했으며 76개 테스트를 통과했다.
9. 완료 — 실제 Supabase 두 탭·모바일·연결 복구를 확인했다. 검토에서 발견한 새 기록 안내 문제를 수정하고 실제 두 탭 회귀 확인, 타입·구문·테스트 76/76·빌드 검사를 통과했다.
10. 진행 중 — 추가 DB 변경은 적용했다. 최종 재검토와 프로덕션 배포·공개 확인을 마치고 문서·원격 소스를 갱신한다.
