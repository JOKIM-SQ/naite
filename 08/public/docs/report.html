한 줄 결론

여러 팀원이 같은 재고를 즉시 확인하는 경우에는 Supabase Realtime을 쓰겠다. 로컬 앱과 실제 원격 Supabase를 연결한 두 탭 20회에서 반영 지연 중앙값 0.536초, p95 0.675초, 최대 0.829초를 관찰했다. 동시 변경·중복 재시도는 DB에서 처리하고 재연결 후 최신값을 다시 읽는다. 5초 폴링도 가능하지만 변경 시점이 고르게 분포한다면 평균 대기 약 2.5초에 통신·렌더링 시간이 더해지고, 두 탭에서 변경이 없어도 분당 24회 조회한다는 계산 때문에 이번에는 Realtime을 선택했다. 로컬 Google 로그인은 사용자 확인 완료, 공개 반환 URL 추가도 완료됐으며 공개 주소에서 인증 후 보드 진입은 최종 확인 대기다. 다시 하면 첫 저장 타이머와 구독 준비 검증부터 시작하겠다.
