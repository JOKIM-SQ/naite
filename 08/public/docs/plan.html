01누가 쓰나

공용 비품이나 상품을 여러 명이 함께 입출고하는 작은 팀의 담당자. 각자 연 화면에서 같은 재고 수량을 확인한다.

02지금은

공유 문서의 재고를 다시 열거나 동료에게 최신 수량을 확인해야 한다. 현재 소요 시간은 기록 없음.

03없앨 동작 하나

다른 팀원의 입출고가 반영됐는지 확인하려고 페이지를 새로고침하는 동작.

04핵심 기능 1개

품목의 수량을 입고·출고하면 원자적으로 저장하고 같은 보드를 보는 다른 탭에 최신 재고와 마지막 변경의 수신 지연을 표시한다. 각 품목의 기록 탭에서 누가 언제 얼마나 변경했는지 전후 수량과 함께 확인한다.

05안 만드는 것 3개

  • 구매·발주 자동화
  • 바코드·CSV·회계 연동
  • 오프라인 재고 수정

06성공 판정

  • 두 탭에서 품목을 등록하고 새로고침 없이 수량과 마지막 수신 지연(ms)이 표시되는지 확인한다. 품목 기록 탭의 수행자·전후 수량, 동시 변경, 연결 복구, 외부 계정 차단도 확인한다.

07내 옵션 + 이유

기존 Supabase Auth와 Postgres를 함께 사용하고 Postgres Changes로 저장된 수량의 변경을 구독한다. 작은 팀의 MVP에서 별도 WebSocket 서버 없이 DB 권한과 동기화를 연결할 수 있다.

08리스크 + 검증법

걱정되는 것: 동시 출고 시 덮어쓰기, 재시도 시 중복 반영, 연결 끊김 중 놓친 변경.
화요일 스파이크로 확인: delta 기반 RPC와 요청 ID로 중복을 방지하고, 재연결 후 최신 스냅샷을 다시 읽는다. 실제 두 탭에서 반영 지연을 관찰한다.
