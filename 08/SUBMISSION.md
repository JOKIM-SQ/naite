S08의 두 탭 조건은 로컬 앱과 실제 원격 DB에서 20회 측정했다. 중앙값 **0.536초**, p95 **0.675초**, 최대 **0.829초**다. 이 수치를 프로덕션에서 새로 측정한 값으로 소개하지 않는다.

## 실제 제출 방법

1. https://initialb.vercel.app/ 의 URL 입력란에 `https://s08-stockroom.vercel.app/`를 넣고 드랍한다.
2. S08의 Stockroom 카드에서 만든 사람·기획서·리포트·소스 링크를 확인한다.
3. https://initialb.vercel.app/compare.html 에 스택 리포트가 반영됐는지 확인한다.

현재 운영 갤러리는 DB를 사용하며 URL 드랍 시 문서의 data-f 값을 자동으로 읽는다. 가이드 본문의 이전 시트/TSV 설명보다 실제 갤러리와 현재 배포된 팀 문서의 제출 절차를 따른다. 별도 슬라이드는 필요 없으며 가이드상 발표 자료는 금지다. 문서를 나중에 고쳤으면 같은 URL을 다시 드랍한다.

**2026-09-24 읽기 전용 점검 시 Stockroom 카드는 아직 없었다. 이 준비 점검에서는 제출을 실행하지 않았다.**

## 3분 시연 순서

1. 공개 앱에서 Google로 로그인하고 같은 보드를 두 탭에 연다.
2. 한 탭에서 품목을 등록하고 다른 탭에 나타나는지 확인한다.
3. 입고·출고 버튼을 눌러 다른 탭 수량 변화를 확인한다.
4. 두 탭에서 같은 품목을 출고하고 최종 수량을 확인한다.
5. 한 탭을 오프라인으로 바꿨다가 복구해 최신 수량을 확인한다.

## 발표에 사용할 근거

- 연결: 끊김 중 변경을 잠그고, 복구 후 DB 최신 스냅샷을 다시 읽는다.
- 충돌: 수량을 덮어쓰지 않고 DB 행 잠금 안에서 delta를 더한다. 같은 요청 UUID는 한 번만 반영한다.
- 폴링 대안: 5초 폴링도 가능하지만 평균 대기는 약 2.5초에 네트워크·렌더링 시간이 더해진다(변경 시점이 고르게 분포한다고 가정한 계산). 두 탭이면 변경이 없어도 분당 24회 조회한다. 즉시 반영이 과제의 목적이므로 Realtime을 택했다.
- 비용: 공식 Free 포함량과 실제 계정 청구는 다르다. 실제 월 사용량·비용은 기록 없음이다.
- 회고: 다시 하면 첫 저장 타이머를 시작하고, Realtime 구독 준비와 첫 이벤트 도착을 가장 먼저 검증하겠다.

## 남은 항목

- 공개 Google 로그인 완료 후 같은 공개 주소로 복귀하고 보드 화면이 열리는지 사용자 확인.
- 공개 주소의 두 탭으로 3분 시연 리허설 및 실제 갤러리 드랍.
- 첫 저장·최초 배포 소요 시간은 당시 시작 기록이 없어 소급해 숫자를 만들 수 없다. 첫 로딩·계정 실제 월 비용도 현재 보고서에는 `기록 없음`이다.
