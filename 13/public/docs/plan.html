01누가 쓰나

제품 사용법을 확인하려는 사용자. 긴 매뉴얼에서 기능의 감독 요건·해제 방법·제한 사항의 정확한 문장을 찾아야 한다. 사용 빈도 실측은 기록 없음.

02지금은

매뉴얼을 열어 목차와 키워드 검색으로 관련 부분을 찾고 직접 읽는다. 현재 탐색 시간과 절감량은 기록 없음.

03없앨 동작 하나

질문의 답이 있는 문장을 긴 매뉴얼에서 수동으로 훑어 찾는 동작을 줄인다.

04핵심 기능 1개

TXT·Markdown 매뉴얼을 넣고 질문하면 Voyage AI 임베딩과 pgvector 검색으로 근거를 찾아 Claude가 출처 문장과 함께 답한다.

05안 만드는 것 3개

  • PDF OCR과 이미지 문서 해석
  • 로그인·팀 권한 관리
  • 웹 검색과 문서 밖 지식으로 답변 보충

06성공 판정

  • 문서에 있는 질문 3개는 출처 문장과 함께 답하고, 없는 질문 1개는 모른다고 답한다. Tesla 샘플의 실제 파일 업로드·7개 청크 저장·3+1 질의·출처 모달 검증을 완료했다. 청킹한 글자 수와 이유를 설명한다.

07내 옵션 + 이유

정적 화면과 Node 서버리스 API를 사용하고 기존 Supabase의 pgvector를 활용해 별도 검색 서버를 줄인다. 임베딩은 Voyage AI, 생성은 Claude로 분리한다. 600자·80자 겹침으로 문맥 경계 손실을 줄인다. 샘플은 제공된 Tesla Model 3(2024+) North America·Software 2026.38.3 매뉴얼의 FSD (Supervised), 인쇄 102~107쪽(PDF 104~109쪽)을 비공식 발췌·요약한 자료다. 원본 PDF 전체는 공개하지 않는다.

08리스크 + 검증법

걱정되는 것: 관련성이 낮은 문서 조각으로 그럴듯한 답을 생성할 수 있다. 무료 토큰과 별개로 요청 속도 제한도 있다. 공개 배포 URL은 기록 없음.
화요일 스파이크로 확인: 실제 Tesla 문서의 있는 질문 3개는 원문 쪽수가 표시된 근거와 답변을 확인했고, 없는 한국 무감독 출시일 질문은 모른다고 답했다. 요청 간 간격을 둔 이번 4건은 모두 첫 시도 성공했다. 다양한 문서에 대한 일반 정확도를 뜻하지 않는다.
