# S13 Folio · 폴리오

제품 매뉴얼을 읽고, 근거 문장과 함께 답한다.

## 사용자와 핵심 기능

제품 사용법을 확인하려는 사람이 긴 매뉴얼에서 해당 문장을 직접 찾는 동작을 줄인다. TXT 또는 Markdown 매뉴얼 하나를 올리고 자연어로 질문하면 관련 문서 조각과 답변 근거를 함께 보여준다. 실사용 시간 절감량은 아직 측정하지 않았다.

## 선택한 구성

정적 HTML/CSS/JS와 Node 서버리스 API로 화면과 비밀키 처리를 나눈다. 기존 Supabase에서 pgvector로 벡터를 저장·검색하므로 별도 벡터 서비스 계정을 추가하지 않는다. 검색용 임베딩은 Voyage AI, 답변 생성은 Claude를 쓴다. 브라우저는 서버 비밀키를 받지 않는다.

## 성공 판정

1. 매뉴얼의 내용이 실제 Voyage 임베딩과 pgvector 저장·검색을 거친다.
2. 문서에 있는 질문 3개에 근거 문장을 포함해 답한다.
3. 문서에 없는 질문 1개에는 답을 추측하지 않고 모른다고 답한다.
4. 출처를 선택하면 해당 원문을 확인할 수 있다.
5. 데모에서 청킹 길이와 겹침, 그렇게 나눈 이유를 설명한다.
6. ‘답을 찾는 과정’에서 실제 질문 벡터 일부, 검색 문단의 유사도, 최종 인용 채택 여부를 단계별로 확인한다. 서버 진행 이벤트로 현재 단계를 표시하고 이전 질문의 과정도 다시 볼 수 있다.

## 시연 자료

기본 자료는 'Tesla Model 3 사용 설명서'다. 사용자가 제공한 Model 3(2024+) North America·Software 2026.38.3 판의 PDF 전체 329쪽 영문 텍스트를 서버에서 사전 인덱싱해 모든 브라우저에 공유한다. 브라우저마다 중복 임베딩하지 않으며 '미리 등록된 매뉴얼'과 개인 TXT/Markdown 문서를 넣는 '내 매뉴얼'을 구분한다. 준비 완료된 기본 자료는 자동 선택한다. 원본 PDF 파일을 공개하지 않고 그림·이미지 OCR은 지원하지 않는다. 차종·지역·버전과 원문 쪽수를 표시한다.

이전 3,689자 요약본은 기기 사용 금지 문장을 누락해 사용자의 전화기 질문에 답하지 못했다. 이후 FSD 6쪽 보완을 거쳐 전체 PDF 텍스트 사전 등록으로 전환한다. 기존 개인 문서는 삭제하지 않는다. 해결은 원문 범위를 보완하는 것이며 검색 임계값을 낮추거나 모델 지식을 덧붙이지 않는다.

## 청킹과 검색

문서는 최대600자씩 나누고 이웃 조각80자를 겹친다. 경계에서 절차가 끊기는 문제를 줄이려는 초기 선택이며 최적값으로 측정된 수치는 아니다. voyage-4-lite512차원 벡터와 pgvector 코사인 유사도0.35이상 상위4개 검색을 쓴다. 실제 전체329쪽 정규화937,449자·1,904개 청크의 임베딩과 저장을 마쳤다. 전화기·타이어 라벨·해제 질문의 근거 답변 및 두 세션 공유 조회를 확인했고, 없는 출시일 질문은 번역 오류 보완 후 새 세션 재시도에서 모른다고 답했다. 최종3+1 통과와 최초 실패를 함께 기록하며 이전 요약본 결과와 구분한다.

## 안 만드는 것

- PDF OCR과 이미지 문서 해석
- 로그인·팀 권한 관리
- 웹 검색과 문서 밖 지식으로 답변 보충

## 검증과 남은 조건

현재 공개 URL은 https://s13-folio.vercel.app/ 이며 홈·기획서·리포트·차량 이미지의 익명 접근을 확인했다. 2026-11-05(PST) production 실제 3+1은 모두 첫 시도에 통과했다. 전화기 3,463ms·타이어 라벨 3,262ms·FSD 해제 3,819ms는 원문을 인용했고 없는 출시일 2,986ms는 인용 0개로 답했다. 위 번역 오류·재시도는 이전 로컬 이력이다. 홈에는 2026 Tesla Model 3 Premium RWD · Stealth Grey 생성 이미지·차량 애니메이션과 움직임 줄이기 대응을 반영했다. 제출 준비를 마쳤으며 initialB에 루트 URL을 실제 등록하는 사용자 작업만 남았다.

자동화 테스트, 실제 외부 API 실행, 브라우저 조작, 공개 배포를 각각 구분한다. Voyage AI 키와 Supabase 스키마 준비가 필요하다. 준비되지 않은 단계는 UI에서 설정 필요 또는 오류로 표시하며 샘플 답변으로 성공처럼 대체하지 않는다. 검증 결과는 SPIKE.md와 SUBMISSION.md에 기록한다.
