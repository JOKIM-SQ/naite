# S07 아이콘·분석 미리보기 코드 리뷰

검토일: 2026-09-17. 읽기 전용 독립 검토이며 이 보고서 외 소스는 변경하지 않았다.

## 판정

강제 고대비 모드에서 삭제 아이콘이 사라지는 접근성 P2 1건을 메인 브라우저 QA로 확정했고 수정 검증을 완료했다. 최신 코드 및 전후 화면 재검토 기준으로 남은 P1/P2 기능·접근성·반응형 회귀는 없다.

## 검토 범위와 확인 결과

- `public/index.html`, `public/styles.css`, `public/analysis-motion.mjs`, `public/analysis-motion.test.mjs`, `public/site.webmanifest`, `public/icons/`, `scripts/dev.mjs`, `scripts/qa-server.mjs`의 현재 변경을 검토했다.
- 그래픽은 ‘정리 과정 미리보기’로 표시한다. SVG는 장식으로 숨겨지고 주변 설명 및 버튼에는 텍스트가 있다. 컨트롤 모듈에서 OCR/API/자동 저장 코드를 호출하지 않는다.
- 최초 50% 노출에서 관찰을 해제하고 한 번 재생한다. CSS 스캔은 3.8초, 상태 타이머는 4.5초이며 기본 스타일은 완성된 정지 그림이다. 재생 중 중복 실행은 차단하고 완료 뒤 다시 보기 버튼으로 재생한다.
- 동작 줄이기 초기 설정은 자동 재생을 막는다. 실행 중 설정 변경은 타이머와 관찰을 취소하고 정지 그림·설명을 표시한다. 설정을 다시 해제해도 자동 재생하지 않고 사용자 재생만 허용한다. 탭이 숨겨져도 멈춘다.
- 새 장식 아이콘은 접근 가능한 기존 작업명을 유지한다. 다시 보기 버튼은 고유한 접근 가능한 이름과 44px 최소 높이를 갖는다. 기존 전역 키보드 포커스 스타일 및 동작 줄이기 CSS가 적용된다.
- 아이콘 PNG 실제 크기는 180×180, 192×192, 512×512이다. 매니페스트의 192/512 크기·경로·PNG 타입 및 HTML 연결 경로가 실제 파일과 일치한다.
- 개발 서버와 QA 서버의 `.mjs` JavaScript MIME은 유지되며, `.webmanifest`에는 `application/manifest+json`, PNG에는 `image/png`를 지정한다. 이 리뷰는 외부 배포 서버의 응답을 검증하지 않았다.
- 폭별 실제 레이아웃·시각 검증은 메인 `/browse` QA의 별도 범위다. 이 리뷰에서 브라우저 또는 배포를 실행하지 않았다.

## P2 수정 검증 완료: 강제 고대비 모드의 삭제 아이콘

원인: `public/styles.css`의 `.remove-item`은 기존 × 문자를 `font-size: 0`으로 숨기고 `::before`의 `background: currentColor` 및 CSS mask로 삭제 아이콘을 표시했다. `forced-colors: active`에서 의사 요소 배경이 흰색으로 강제되면서 흰색 부모 배경과 겹쳐 삭제 동작을 시각적으로 찾을 수 없었다.

메인 `/browse` QA가 실제 브라우저에서 의사 요소의 계산된 배경색 `rgb(255, 255, 255)`와 아이콘 소실을 재현했다. 독립 리뷰에서도 [수정 전 화면](animation/forced-colors-before.png)을 열어 품목 행 끝의 아이콘 부재를 확인했다.

수정: CSS 마지막의 `@media (forced-colors: active)`에서 원본 링크·품목 삭제·분석 재시도 세 mask 아이콘의 의사 요소에 `forced-color-adjust: none; background: ButtonText;`를 적용한다. 시스템 전경색을 명시하므로 사용자 고대비 팔레트를 따르면서 배경 강제 치환으로 아이콘이 사라지는 문제를 막는다. 일반 모드 스타일·접근 가능한 이름·버튼 크기·이벤트 핸들러는 변경하지 않는다.

검증: 최신 CSS에서 세 선택자와 두 선언을 다시 확인했고, [수정 후 화면](animation/forced-colors-after.png)에서 품목 행 끝의 삭제 아이콘이 나타나는 것을 독립 확인했다. 메인 브라우저 QA는 수정 후 계산된 배경색이 검정이며, 접근 가능한 삭제 이름·44px 조작 영역·실제 삭제 클릭 동작이 정상임을 확인했다. 이 리뷰에서는 브라우저를 별도로 조작하지 않았다.

최종 상태: **해결됨. 남은 P1/P2 없음.**
