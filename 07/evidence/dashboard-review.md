# S07 카테고리 대시보드 검증 — 2026-09-17

## 범위
구매 품목을 제거하고 네 카테고리 자동 분류, 카드 기록, 편집·삭제 대화상자, 사이드바, KPI와 월별·카테고리별 지출을 구현했다. 기존 OAuth와 개인별 원본 저장 흐름을 유지한다. 기존 카테고리 없는 기록은 그 외로 표시한다.

## 자동 검사
최종 코드에서 npx tsc --noEmit, npm run lint, npm test, npm run build, git diff --check 성공. 테스트 134개 통과, 실패·건너뜀 없음. TypeScript 설정은 allowJs/checkJs:false이므로 엄격한 JS 타입 검사 결과로 해석하지 않는다.

API 경계에는 계정 격리, 전체 기록 커서 조회, 삭제 상태 예약과 실패 복구, 오래 멈춘 분석 삭제 및 늦게 도착한 분석 응답 거부가 포함된다. 통계는 확정된 저장값, 혼합 통화, 없는 날짜·금액, 0원, 소수 금액, 월·연도 경계를 검증한다.

## 브라우저 관찰
실제 app.js와 API를 실행하는 로컬 QA 서버(3099)에서 /browse로 조작했다. Auth·Storage·OCR 외부 응답은 테스트용이다. 화면의 QA 계정과 상호명·금액은 가상 데이터이며 실제 AI 정확도나 운영 DB 성공의 증거가 아니다.

## 독립 검토와 수정
s07_dashboard_review 에이전트가 구현을 읽고 다음 경계를 지적했으며 재검토에서 수정 확인 및 추가 확정 결함 없음으로 반환했다.

- 편집 직후 닫기: 현재 필드 확정 후 자동 저장 큐를 기다리고 오류 시 닫지 않음.
- 삭제 revision 충돌: 최신 값과 편집 상태·삭제 확인 정보를 동기화.
- 미저장 값 집계: confirmedValues/confirmedRevision으로 서버 확인값만 계산.
- 통화가 다른 새 카드 숨김: 금액 집계와 카드 필터를 분리.

## 운영 의존성
SUPABASE-DELETE-MIGRATION.sql은 기존 데이터 변경 없이 deleting 상태와 service_role DELETE 권한을 추가한다. 현재 Supabase CLI는 프로젝트 조회는 되지만 SQL 실행에서 토큰을 인식하지 못했다. 사용자에게 정확한 SQL 파일 적용을 요청했고 적용 확인을 기다린다. 신규 운영 삭제, 실제 Haiku 분류 및 이번 대시보드 공개 배포는 아직 확인하지 않았다.
