01누가 쓰나

관심 있는 Amazon 상품을 나중에 비교하거나 다시 찾기 위해 저장하는 개인 리서처. 상품 URL만 모아두면 제품명과 카테고리를 다시 적어야 해, 저장한 목록을 태그로 정리하기 어렵다.

02지금은

Amazon 상품을 발견할 때마다 URL을 복사해 메모장이나 브라우저 북마크에 쌓는다. 제품명·가격·이미지·카테고리 정보가 URL과 분리되고, 같은 종류의 상품만 다시 보려면 하나씩 열어 확인해야 한다.

03없앨 동작 하나

상품 URL을 저장한 뒤 제품 정보와 카테고리를 손으로 다시 적는 것. Amazon URL 하나를 드롭해 제품 정보와 Amazon PDP의 카테고리 태그를 최대 3개까지 자동으로 채우는 것으로 대체한다.

04핵심 기능 1개

Amazon URL을 드롭하면 서버 함수가 ASIN·제품명·현재 표시 가격·대표 이미지·Amazon PDP 카테고리의 앞 3단을 읽는다. PDP에 카테고리가 없으면 제품은 태그 없이 저장되고 카드와 필터에 ‘카테고리 없음’으로 표시된다. 사용자가 확인한 제품은 Supabase의 weekly_projects.s02_products·s02_tags·s02_product_tags에 저장되고, 태그를 누르면 연결된 제품만 보인다. 사용자는 별도의 커스텀 태그도 붙이고 편집·삭제할 수 있다.

05안 만드는 것 3개

  • Amazon 대량 수집 — 상품 URL을 하나씩 저장하고, 가격은 보관한 상품만 매일 1회 확인한다
  • 로그인·계정별 보관함 — 개인 공개 보관함으로 운영하고, 항목 삭제는 임시 4자리 PIN으로만 보호한다
  • 가격 이력 차트·알림 — 전일 대비 상승·하락 배지만 표시하고, 상세 추이와 알림은 다음 버전으로 남긴다

06성공 판정

  • Amazon URL 3개에서 제품명·표시 가격·대표 이미지·PDP 카테고리 태그가 최대 3개까지 자동으로 채워진다
  • PDP에 카테고리가 없는 제품은 태그 없이 저장되고 ‘카테고리 없음’ 필터로 확인할 수 있다
  • 두 제품이 공유하는 태그를 선택하면 두 제품이 함께 필터된다
  • 새로고침과 다른 브라우저에서도 저장한 제품 목록이 보인다
  • 자동 추출 실패 시 ASIN을 유지한 채 제품 정보를 직접 입력해 저장할 수 있다

07내 옵션 + 이유

Supabase를 고른 이유는 이번 주의 핵심인 다대다 태그를 Postgres 관계로 직접 표현하기 위해서다. weekly_projects 스키마에 s02_products·s02_tags·s02_product_tags 세 테이블을 두면 제품 하나에 Amazon 카테고리 태그를 최대 3개 붙이고, 태그가 없는 제품도 함께 보관할 수 있다. Furniture 같은 태그 하나가 여러 제품을 가리키는 구조를 읽기와 필터에서 그대로 확인할 수 있다. 서버 함수가 Supabase REST API만 호출하므로 별도 백엔드 서버를 만들지 않는다.

08리스크 + 검증법

걱정되는 것: Amazon은 요청 주체에 따라 상품 HTML 대신 중간 페이지나 방어 응답을 돌려줄 수 있다. 현재 서버 HTTP fetch로는 세 상품을 각각 세 번 요청해 제목·가격·이미지·카테고리 추출에 성공했지만, 배포 함수 IP에서는 결과가 달라질 수 있다.
화요일 스파이크로 확인: Supabase에 Product 1개와 Tag 2개를 실제 저장·조회하고, 배포 함수에서 세 상품 URL을 다시 읽는다. 자동 추출이 실패하면 ASIN만 URL에서 정규화하고 나머지를 수동 입력하는 폴백으로 저장이 막히지 않게 한다.
