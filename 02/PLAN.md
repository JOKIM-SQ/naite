# S02 기획서 초안 — Cart [+] Hoarders

| | |
|---|---|
| 스프린트 | S02 (2026-08-10 ~ 08-14) |
| 스택 카드 | 데이터 저장 |
| 내 옵션 | Supabase (Postgres) |

Amazon 상품 URL을 드롭하면 제품 정보를 읽고 카테고리 태그를 붙여 Supabase에 저장한다.
저장한 제품을 태그로 필터해 카테고리 기반의 개인 스크랩북으로 본다.

## 핵심 기능

1. Amazon URL을 드롭한다.
2. 서버 함수가 ASIN, 제품명, 현재 표시 가격, 대표 이미지 URL, 카테고리 브레드크럼을 읽는다.
3. 브레드크럼의 실제 앞 3단을 카테고리 태그로 정리한다.
4. 사용자가 저장하면 제품과 태그가 Supabase에 저장된다.
5. 제품 목록을 읽고 태그로 필터한다.

## 성공 판정

- Amazon URL 3개에서 제품명·표시 가격·대표 이미지 URL·카테고리 태그 3개를 자동 채운다.
- 상품마다 카테고리 태그 3개가 실제 저장된다.
- Supabase에서 저장한 상품 목록이 조회되고 태그 필터가 동작한다.
- `Furniture`처럼 두 상품이 공유하는 태그를 선택하면 두 상품이 함께 보인다.
- `Furniture`처럼 두 상품이 공유하는 태그가 `s02_product_tags` 관계로 저장된다.
- 첫 화면에서 URL을 어디에 넣고, 저장한 제품을 어디서 태그로 거르는지 5초 안에 읽힌다.
- ASIN 또는 제품명으로 보관함을 검색하고, 사용자가 붙인 커스텀 태그는 Amazon 카테고리와 분리해 편집·삭제할 수 있다.
- 매일 태평양 시간 오전 6시에 표시 가격을 비교해 상승·하락 상태를 카드에 표시한다.

## UI 방향

- 제품 스크랩북이므로 일반 대시보드 대신 선반과 수집 현황의 인상을 준다.
- 상단에는 URL 드롭 동작을 가장 크게 두고, 저장 전 제품 미리보기는 같은 화면에서 바로 확인·수정한다.
- 제품 카드는 이미지·가격·ASIN·카테고리 태그를 한 장에 보이며, 태그 필터는 카드 위에 둔다.
- Supabase 미연결 상태도 빈 화면으로 숨기지 않고, 연결 준비가 필요하다는 상태를 보여준다.

## 공통 데이터 모델

```text
Product
  asin, source_url, title, displayed_price, image_url, tags[]

Tag
  key: 전체 경로 기반 식별자
  label: 화면에 보이는 단계명
  level: 1 | 2 | 3
```

태그는 같은 라벨이 다른 경로에서 충돌하지 않도록 전체 카테고리 경로를 `key`로 쓴다.
화면에는 단계명 `label`만 표시한다.

## Supabase 다대다 표현

`s02_products` · `s02_tags` · `s02_product_tags` 세 테이블을 쓴다. 제품 하나는 카테고리 태그 3개를 가지고,
하나의 태그는 여러 제품에 연결된다.

## 자동 추출과 폴백

- Amazon은 브라우저에서 직접 요청하지 않는다. 서버 함수가 HTML을 fetch한다.
- 현재 로컬 스파이크에서는 상품 3개 × 3회가 모두 HTTP 200, 제목·표시 가격·대표 이미지·카테고리 추출에 성공했다.
- Vercel 배포 환경에서도 같은 세 URL로 재검증한다.
- 자동 추출이 실패하면 ASIN만 URL에서 정규화하고 제품명·가격·이미지·태그를 수동 입력해 저장한다.

## 안 만드는 것

1. Amazon 자동 스크래핑의 성공 보장, 대량 수집
2. 로그인
3. 정렬, 통계 대시보드

## 화요일 스파이크 합격 조건

- Supabase에 최소 Product 1개와 Tag 2개를 실제로 쓰고 다시 읽는다.
- Supabase 키는 서버 함수 환경변수에서만 사용한다.
- Amazon fetch가 배포 함수 환경에서도 세 상품의 제목을 읽는지 확인한다.
