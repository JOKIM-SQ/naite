# S02 기획서 초안 — ASIN 스크랩북 DB 비교기

| | |
|---|---|
| 스프린트 | S02 (2026-08-10 ~ 08-14) |
| 스택 카드 | 데이터 저장 |
| 내 옵션 | Supabase · Firestore · Airtable · localStorage 비교 |

Amazon 상품 URL을 드롭하면 제품 정보를 읽고 카테고리 태그를 붙여 네 저장소에 각각 저장한다.
같은 제품을 저장소별로 읽고 태그로 필터하며, 저장 구조와 읽기 경로의 차이를 보여준다.

## 핵심 기능

1. Amazon URL을 드롭한다.
2. 서버 함수가 ASIN, 제품명, 현재 표시 가격, 대표 이미지 URL, 카테고리 브레드크럼을 읽는다.
3. 브레드크럼의 실제 앞 3단을 카테고리 태그로 정리한다.
4. 사용자가 저장하면 같은 제품과 태그가 Supabase, Firestore, Airtable, localStorage에 각각 저장된다.
5. 저장소를 선택해 목록과 태그 필터 결과를 보고, 목록 읽기와 태그 필터의 5회 측정 중앙값을 비교한다.

## 성공 판정

- Amazon URL 3개에서 제품명·표시 가격·대표 이미지 URL·카테고리 태그 3개를 자동 채운다.
- 상품마다 카테고리 태그 3개가 실제 저장된다.
- 네 저장소 모두에서 저장한 상품 목록이 조회되고 태그 필터가 동작한다.
- `Furniture`처럼 두 상품이 공유하는 태그를 선택하면 두 상품이 함께 보인다.
- 각 저장소의 데이터 표현과 읽기 경로를 한 화면에서 설명한다.
- 읽기 시간은 같은 조건에서 5회 측정한 중앙값으로 표시한다. 절대 성능 순위로 해석하지 않는다.

## 공통 데이터 모델

```text
Product
  asin, source_url, title, displayed_price, image_url, tags[]

Tag
  key: 전체 경로 기반 식별자
  label: 화면에 보이는 단계명
  level: 1 | 2 | 3
```

태그는 같은 라벨이 다른 경로에서 충돌하지 않도록 전체 카테고리 경로를 `key`로 쓴다.
화면에는 단계명 `label`만 표시한다.

## 저장소별 다대다 표현

| 저장소 | 표현 |
|---|---|
| Supabase | `products` · `tags` · `product_tags` |
| Firestore | 제품 문서의 `tags` 배열 |
| Airtable | Products ↔ Tags linked records |
| localStorage | 제품 객체의 `tags` 배열 |

## 자동 추출과 폴백

- Amazon은 브라우저에서 직접 요청하지 않는다. 서버 함수가 HTML을 fetch한다.
- 현재 로컬 스파이크에서는 상품 3개 × 3회가 모두 HTTP 200, 제목·표시 가격·대표 이미지·카테고리 추출에 성공했다.
- Vercel 배포 환경에서도 같은 세 URL로 재검증한다.
- 자동 추출이 실패하면 ASIN만 URL에서 정규화하고 제품명·가격·이미지·태그를 수동 입력해 저장한다.

## 안 만드는 것

1. Amazon 자동 스크래핑의 성공 보장, 대량 수집, 가격 추적
2. 네 저장소 간 동기화, 재시도, 충돌 해결, 데이터 마이그레이션
3. 로그인, 수정·삭제, 검색, 정렬, 통계 대시보드

## 화요일 스파이크 합격 조건

- 네 저장소 각각에 최소 Product 1개와 Tag 2개를 실제로 쓰고 다시 읽는다.
- Airtable 자격 증명은 서버 함수 환경변수에서만 사용한다.
- Firestore의 공개 읽기·쓰기가 로그인 없이 가능한 규칙인지 확인한다.
- Amazon fetch가 배포 함수 환경에서도 세 상품의 제목을 읽는지 확인한다.
