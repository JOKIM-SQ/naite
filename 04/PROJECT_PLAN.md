# S04 기획서 — caramelcaramelcaramel

> Amazon 가격 추적 서비스 · 제출 버전 v1.0 · 2026-08-25

## 1. 프로젝트 개요

### 문제 정의

Amazon 상품은 가격과 별점이 자주 달라지지만, 사용자가 직접 매일 확인하기는 번거롭다. 상품을 한 번 저장하면 가격·별점의 변화를 누적해서 보고, 가장 적절한 구매 시점을 판단할 수 있는 서비스가 필요하다.

### 서비스 제안

**caramelcaramelcaramel**은 Amazon ASIN URL을 입력해 상품을 보관하고, 매일 수집한 가격과 별점을 이력으로 보여주는 가격 추적 서비스다. camelcamelcamel의 가격 추적 개념을 바탕으로, 카라멜·사막·낙타 캐러밴을 이용한 독자적인 카드형 UI를 적용한다.

### 프로젝트 목표

1. Amazon URL 하나로 상품명, 가격, 별점, 이미지, 카테고리를 추출한다.
2. 저장한 상품의 가격과 별점을 매일 영구 저장한다.
3. 가격·별점 각각의 이력과 최신 변화 상태를 한 화면에서 이해하게 한다.
4. S02 Cart Hoarders의 계층형 카테고리 탐색 경험을 이어받는다.

## 2. 사용자와 핵심 시나리오

| 사용자 | 상황 | 해결 방식 |
| --- | --- | --- |
| 합리적 구매자 | 관심 상품이 언제 저렴해지는지 알고 싶다. | 가격 이력 그래프와 가격 상승·동일·하락 배지를 확인한다. |
| 상품 비교 사용자 | 별점 변동도 구매 판단에 반영하고 싶다. | 별점 이력 그래프와 별점 변화 배지를 확인한다. |
| 여러 상품을 모으는 사용자 | 저장 상품이 늘어나면 찾기 어렵다. | ASIN/제품명 검색과 1~3단계 카테고리 필터를 사용한다. |

### 대표 사용자 흐름

1. 사용자가 Amazon 상품 URL을 붙여 넣고 `READ PRICE`를 누른다.
2. 서버가 ASIN을 정규화하고 Amazon HTML을 읽는다.
3. 제목과 가격이 확보되면 사용자는 정보 확인 후 `TRACK IT`으로 저장한다.
4. 첫 가격·별점 스냅샷과 카테고리 태그가 Supabase에 저장된다.
5. 매일 오전 6시 태평양 시간 크론이 저장 상품을 다시 읽어 새 스냅샷을 기록한다.
6. 사용자는 카드의 변화 배지를 보거나 카드를 눌러 가격/별점 이력을 전환해 확인한다.

| 카드 가독성 | 긴 제목 한 줄 marquee, 계층별 카테고리 칩 | 제목·태그가 카드 이미지 위에서도 식별된다. |

## 4. 화면 및 인터랙션 설계

### 메인 화면

- 상단: 브랜드 아이콘과 매일 06:00 PT 수집 안내
- 히어로: 사막이 가로로 흐르고, 세 마리 낙타가 서로 다른 카트를 지며 가격표 캔디가 떨어지는 애니메이션
- 입력: Amazon 상품 URL 입력과 수집 상태 메시지
- 컬렉션: 검색, S02식 계층 필터, 저장 상품 카드

### 상품 카드

- 긴 제목은 카드 너비를 넘을 때만 한 줄 반복 marquee로 노출한다.
- 가격과 별점은 핵심 숫자로 강조한다.
- `가격 ↑/동일/↓`, `별점 ↑/동일/↓` 배지는 카테고리와 분리한다.
- Amazon 카테고리는 Level 1 진한 카라멜, Level 2 연한 카라멜, Level 3 윤곽 칩으로 표시한다.
- 카드는 최대 3개 태그를 표시하고 나머지는 `+N`으로 요약한다.

### 상품 상세

- 가격 / 별점 탭으로 같은 수집 시점의 두 지표 이력을 전환한다.
- 1개월, 3개월, 6개월, 1년, 전체 기간 필터를 제공한다.
- 그래프 아래에 최저·최고·현재·평균 값을 표시한다.

## 5. 기술·데이터 설계

### 기술 스택

| 구분 | 선택 | 용도 |
| --- | --- | --- |
| 프런트엔드 | 정적 HTML, CSS, Vanilla JavaScript | 카드 UI, 필터, 상세 그래프, 애니메이션 |
| 서버 | Vercel Functions (Node.js) | Amazon 수집, 상품/이력 API, 크론 핸들러 |
| 파싱 | HTTP fetch + Cheerio | Amazon HTML에서 상품 정보 추출 |
| 데이터베이스 | Supabase Postgres | 영구 상품·태그·가격/별점 이력 저장 |
| 스케줄러 | Vercel Cron | 매일 가격·별점 재수집 트리거 |
| 배포 | Vercel | 정적 페이지와 API 운영 배포 |

### 데이터 모델

```text
s04_products
  └─ 상품 기본 정보, 마지막 가격, 마지막 별점 변화 상태

s04_tags
  └─ Amazon 계층 카테고리 또는 사용자 커스텀 태그

s04_product_tags
  └─ 상품과 태그의 N:M 연결

s04_price_checks
  └─ 수집 시각, 가격, 별점, 가격 변화, 별점 변화의 누적 이력
```

가격과 별점 변화 상태는 각각 이전 값과 현재 값을 비교해 `-1(하락)`, `0(동일/비교 불가)`, `1(상승)`으로 저장한다.

### 일일 수집 정책

1. Vercel Cron은 UTC 13시와 14시에 호출된다.
2. 서버는 `America/Los_Angeles` 기준 오전 6시일 때만 실제 수집을 실행해 서머타임을 처리한다.
3. 상품별로 50회 수집 뒤에도 필수 정보가 누락되면 짧게 대기한 뒤 두 번째 50회 수집 사이클을 실행한다.
4. 가격이 처음 확인되는 즉시 가격 스냅샷을 먼저 저장한다.
5. 이미지·별점·카테고리 같은 메타데이터는 이후 재시도 중 채워진 값만 보강한다.

이 정책으로 Amazon 응답이 부분적으로 누락돼도 가격 이력 자체가 메타데이터 누락 때문에 막히지 않게 한다.

## 6. 운영 환경과 보안

| 환경변수 | 역할 |
| --- | --- |
| `SUPABASE_URL` | Supabase 프로젝트 URL |
| `SUPABASE_SERVICE_ROLE_KEY` | 서버 전용 DB 접근 키 |
| `CRON_SECRET` | 크론 요청 인증 값 |
| `DELETE_PIN` | 상품 삭제 확인 PIN |

- 서비스 키와 비밀값은 `.env.example`에 값 없이 이름만 제공하며 Git에 실제 값을 저장하지 않는다.
- 크론 엔드포인트는 `Authorization: Bearer <CRON_SECRET>` 인증이 있어야 실행된다.
- 데이터베이스 스키마·RLS·권한 설정은 `SUPABASE.sql`로 재현 가능하다.
