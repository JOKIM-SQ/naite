# S12 기획 — 주차노트 · Weeknote

## 과제와 사용자

S12 실제 미션은 **MCP 서버 만들기**다. 기준 원문은 [initialB 가이드 S12](https://initialb.vercel.app/guide.html#s12)다. 주차 과제를 확인하려는 John Kim이 AI에게 질문할 때 공식 가이드에서 해당 주차를 찾아 복사하는 동작을 줄인다. 현재 수작업 빈도와 소요 시간은 기록 없음이다.

## 핵심 기능 1개

AI 클라이언트가 `get_assignment({ "week": "s12" })`를 호출하면 서버가 고정 가이드 URL을 가져오고 선택한 주차의 제목·미션·골·제약·출처·조회 시각을 반환한다. 도구 1개·데이터 소스 1개·핵심 기능 1개로 범위를 제한한다.

## 선택과 범위

공식 TypeScript MCP SDK `1.32.2`와 로컬 stdio를 사용한다. Node.js 22.22.3에서 설치·빌드·실행을 검증한다. 과제 조회에 계정·API 키가 필요하지 않아 연결 구조를 작게 유지할 수 있다. AI 모델은 연결한 클라이언트가 제공한다.

만들지 않는 것은 ① 임의 URL·로컬 파일 조회와 쓰기 도구, ② DB·로그인·LLM 서버, ③ 별도 채팅 UI다. 정적 소개 페이지에는 기능·권한·연결 방법과 팀 문서 링크를 제공한다.

| 시나리오 | 확인할 결과 | 현재 상태 |
| --- | --- | --- |
| MCP Inspector 목록 조회 | `get_assignment` 도구와 입력·설명 확인 | 확인 |
| Inspector `week: "s12"` 호출 | 실제 가이드 S12 제목·미션·골·제약·출처·조회 시각 반환 | 확인 |
| 잘못된 입력·조회 실패 | 성공 예시로 대체하지 않고 오류 반환 | URL 입력 오류 및 자동 테스트 확인 |
| AI 클라이언트 도구 선택 | 같은 과제 질문에서 실제 MCP 호출과 결과 사용 확인 | Claude Haiku 5.5에서 실제 1회 호출 확인 |
| 연결 전후 비교 | 같은 질문의 두 결과·출처·연결 시간·설명·권한 범위를 기록 | 도구 호출 0회→1회, SDK 새 연결 173ms 1회 관측 |
| 소개 페이지와 문서 | 3120 소개 페이지 및 두 팀 문서가 열리고 메타데이터 일치 | 로컬 확인, 최초 공개 배포·비로그인 HTTP 200 확인 |
| 정적 검사·테스트·빌드 | 타입 검사·lint·전체 테스트·build 성공 로그 | 최근 기록 13/13 테스트·나머지 검사 성공 |

결과와 증거 경로는 [제출 체크리스트](SUBMISSION.md)에 기록한다. 공개 주소는 [https://s12-weeknote.vercel.app/](https://s12-weeknote.vercel.app/)이며 최초 배포·비로그인 접근을 확인했다. 서버 createdAt→ready 구간 0.23분, 브라우저 첫 탐색 0.20초는 각 1회 관측이다. initialB 실제 등록은 실행하지 않는다. 173ms는 SDK 초기화 한 번의 관측이며 전체 셋업 시간이나 일반 성능을 뜻하지 않는다.

## 리스크와 검증

공식 가이드의 HTML 구조가 바뀌면 주차 추출이 실패할 수 있다. 원문을 실제로 가져오는 호출과 고정 fixture 기반 파서 테스트를 함께 사용하고, 구조 오류는 명시적으로 반환한다. stdout에 진단이 섞이면 MCP 통신이 깨질 수 있으므로 실제 stdio 목록·호출로 확인한다. 클라이언트 연결 성공과 도구가 실제 선택되었다는 증거를 구분한다.

## 제출 구성

소개 사이트 루트, `/docs/plan.html`, `/docs/report.html`을 준비한다. 팀 템플릿의 레이아웃·CSS·`data-f`와 복사 스크립트를 유지한다. [소스](https://github.com/JOKIM-SQ/naite/tree/codex/s12-weeknote-mcp/12)를 연결하고, 공개 배포 후 소개 사이트 URL 하나로 initialB 등록을 준비한다. Inspector CLI의 목록·호출 재현 명령과 Claude 연결 비교는 README·제출 체크리스트에 남긴다. 실제 등록은 실행하지 않는다.
